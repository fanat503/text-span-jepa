# seed-7
finding: `config/scaling/devices/` passes seven guard tests that certify a weak-scaling invariant whose device factor — `_meta.devices` — is read by nothing outside the test file itself. The family is documentation with a test suite attached; no launcher can produce the device counts it claims to sweep over.
evidence: the arithmetic **is** correct as written. `_meta.devices x data.batch_size x optimization.grad_accum_steps` = 1x512x1, 2x256x1, 4x128x1, 8x64x1 -> all 512, equal to `_effective_batch(_DEFAULTS)` = `defaults.yaml:60 batch_size: 64` x `defaults.yaml:283 grad_accum_steps: 8`. `tests/test_config_system.py:870-886` asserts exactly this.
  But `_meta.devices` has exactly **two** readers in the repository, both inside `tests/test_config_system.py` (`:864` and `:875`). Repo-wide grep for a read of that key returns only those two lines. No `src/` code, no CLI flag and no script reads it — the files' own headers say so ("Device count is a LAUNCHER argument ... this file deliberately does not invent a flag for it", `dev1_bs512.yaml:19-22`).
  Consequence, given the already-known DDP findings (no `DistributedSampler`, no `init_process_group`, no `local_rank`): the invocation each file recommends — `torchrun --nproc_per_node=8 -m src.train --fname config/scaling/devices/dev8_bs64.yaml` — produces 8 independent single-device replicas, each stepping on a 64-sequence batch, with gradients never summed and all 8 writing to the same `output/scaling/devices/dev8-bs64/`. The measured global effective batch would be **64, not 512**, and "the number of optimizer steps per epoch stays identical" (the file's stated purpose, `dev1_bs512.yaml:13-17`) would be true across all four rungs only because all four would be running the *same* 64-batch single-device job.
  The family was added during setup and has never been run by anything.
benefit: 4
proposed_card: goal — stop the guard suite from certifying an unreachable invariant. Either (a) delete `config/scaling/devices/` and `TestFixedSizeDistributedFamily` until DDP exists, or (b) keep the configs but rename the class and rewrite its docstring to say what it actually asserts ("the four rungs agree on the reference shape and declare a device count for the future launcher"), and change `test_global_effective_batch_is_held_fixed` to assert `batch_size x accum` equals the reference **without** the `_meta.devices` factor, so the test stops implying an end-to-end property. files_allowed: `config/scaling/devices/*.yaml` (headers), `tests/test_config_system.py` (class only). verify — `pytest tests/test_config_system.py -q -k Distributed` green, and the class name/docstring no longer claims to validate steps-per-epoch.
