finding: the three Kaggle configs — the one place in the repo where JEPA, MLM and data2vec are configured with identical hardware, identical effective batch (32 x 16 = 512) and an identical corpus — all declare the same `logging.folder`, so the three arms overwrite each other's checkpoints and logs.
evidence: `config/kaggle/textspanjepa_kaggle.yaml:55`, `config/kaggle/mlm_kaggle.yaml:41` and `config/kaggle/data2vec_kaggle.yaml:44` all set `logging.folder: /kaggle/working/output/`.
  `src/train.py:1180-1181` — `log_dir = log_cfg.get("folder", "output/")`; `os.makedirs(log_dir, exist_ok=True)`. The value is used **verbatim**: no per-config or per-model subdirectory is appended. Every artefact name is a fixed literal: `params-text-span-jepa.yaml` (:1185, hard-coded string — an MLM or data2vec run writes a file named after JEPA), `train_log.csv` (:1190), `checkpoint-latest.pth.tar` (:1216), `checkpoint-ep{n}.pth.tar` (:1599), `best.pt` (:1569).
  `scripts/kaggle/train.sh:10` passes no `--output_dir`, and `run_experiment.sh` passes `--output_dir` only for the wikitext arms. So `bash scripts/kaggle/train.sh` three times with the three configs yields one directory holding whichever arm ran last.
  This is distinct from the known DDP finding (same folder across ranks of one run): here it is three *sequential* runs of three different models, which is exactly the comparison the Kaggle profile exists to support.
