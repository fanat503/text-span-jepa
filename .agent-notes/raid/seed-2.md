finding: the JEPA-vs-MLM comparison is not token-budget matched — the JEPA arm gets **3.89x more prediction targets** per run than the baseline it is compared against, from two independent multipliers (mask budget 0.35 vs 0.15, epochs 50 vs 30).
evidence: `src/masks/span.py:53` — `target_num_masked = int(seq_len * self.current_mask_ratio)`, so `data.mask_ratio` is the fraction of *tokens* turned into supervised targets, independent of span length. JEPA arms inherit `defaults.yaml:65 mask_ratio: 0.35`; `config/wikitext/mlm_wikitext_small.yaml:34` and `config/kaggle/mlm_kaggle.yaml:29` / `config/kaggle/data2vec_kaggle.yaml:30` set `mask_ratio: 0.15`. Ratio 0.35/0.15 = **2.333x** targets per sequence.
  Epochs: `defaults.yaml:274 epochs: 50` for JEPA; `mlm_wikitext_small.yaml:45 epochs: 30` and `mlm_kaggle.yaml:35 epochs: 30` for the baseline. Ratio **1.667x**.
  Product: 2.333 x 1.667 = **3.89x more prediction targets** for JEPA. lr also differs (1e-3 vs 5e-4), which is defensible as per-method tuning and is not counted here.
  Partially disclosed: `mlm_wikitext_small.yaml:17-22` and `data2vec_wikitext_train.yaml:17-22` both say "The three methods therefore do not see the same token budget ... reconciling it is an experiment decision". So the config authors knew. What is not recorded anywhere is the *magnitude* (3.89x) and the fact that the mask-budget term, not the epoch term, is the larger half.
