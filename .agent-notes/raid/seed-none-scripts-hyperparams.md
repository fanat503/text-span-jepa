# seed-none-scripts-hyperparams
area: the question the card asked — "do the hyperparameters hard-coded in `scripts/` agree with the configs they invoke? A script that overrides a config on the command line is a hidden experiment."

answer: **There are no hyperparameter overrides in `scripts/` at all.** Zero. Negative result, so the "hidden experiment" failure mode the card was worried about does not exist in this repo. The real defect in `scripts/` is a different one and is filed separately as `seed-6`.

evidence — all 8 files, read in full:
  - `scripts/wikitext/train_small.sh`, `train_base.sh`, `train_large.sh`, `train_ddp.sh`, `scripts/tinystories/train.sh`, `scripts/fineweb/train.sh`, `scripts/kaggle/train.sh`: the only argument passed to `python -m src.train` is `--fname "$CONFIG"` (plus `--nproc_per_node` in the DDP case). Every schedule value — batch size, accumulation, epochs, lr, mask ratio, EMA endpoints, mechanism flags — comes from the config file through the defaults merge.
  - `scripts/run_experiment.sh`: same. `--fname <path>` and `--output_dir <path>` only, in all 8 `case` arms (:27-29, :34-36, :41-43, :48-50, and the `compare*` arms which call `src.interp.run_comparison`). The `ablation`, `scaling`, `validate` and `index` arms (:71-194) embed inline `python -c` scripts, but those build `TextSpanJEPAConfig(vocab_size=1000, max_seq_len=32, embed_dim=64, encoder_depth=2, ...)` from literal scratch and train on `torch.randint` — they are smoke demos on synthetic data, not experiments, and they touch no shipped config. Their CLI flags do match `run_comparison.py`'s argparse exactly (`--jepa_ckpt` :381, `--baseline_ckpt` :382, `--baseline_type` :388, `--output` :395-396, `--max_batches` :406) — no broken-flag finding there.

what I checked and found clean in the same pass:
  - Config *targets* all exist. Every `--fname` path in every script resolves to a real file, including `config/wikitext/data2vec_wikitext_train.yaml`, which looks like a typo for `_base_` but is a real file (`_meta.config: data2vec_base`, base-140m rung). See `seed-4` for what that file's existence costs.
  - CLI flag names in `run_experiment.sh` match the argparse definitions in `src/interp/run_comparison.py` and `src/train.py:1749` (`--output_dir`, `--fname`, `--no_defaults`).
  - The Windows claim in the card is confirmed and is a deployment fact, not a defect: none of the 8 run on this host (`#!/bin/bash`, `set -euo pipefail`, `$(cd "$(dirname "$0")/.." && pwd)`, `CUDA_VISIBLE_DEVICES=0`, `torchrun`). That is a portability statement, not a correctness finding, so no seed. One cosmetic inconsistency for whoever tidies: `scripts/tinystories/train.sh` is the only file using bare `set -e` (`:2`) and the only one missing the Apache-2.0 line that the other seven carry.
  - No script writes to a path outside its config's `logging.folder` or `--output_dir`. (The shared-`logging.folder` collision is in `config/`, not `scripts/` — filed as `seed-5`.)
