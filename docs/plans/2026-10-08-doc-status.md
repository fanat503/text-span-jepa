# Documentation status index — what is current, what is dated, what was voided

Written 2026-10-08 by TASK-41. One page, because the alternative is a reviewer
finding a stale number in a dated document and believing it.

## The rule this repo follows

**A dated record stays dated and is marked; it is not rewritten.** "As of
2026-08-24, this was wrong, superseded by TASK-30" is useful. A silently edited
audit is worse than a wrong one, because nobody will look at it again.

The corollary is that this file must exist. A date in a document is not a status.

## The second failure mode: `file.py:NNN` citations

A `file.py:NNN` in prose is a **number in a document**, with the same failure
mode as any other: it stops being true the moment anything above it is
inserted, and nothing notices. Found by extracting every such citation from
`README.md`, `AGENTS.md`, `config/ablations/README.md`, `proofs/**`,
`docs/related_work.md` and `docs/decisions.md` and printing the line each one
points at.

**All six `jawp.py` line numbers in `proofs/README.md`'s capability table had
drifted, by 84–85 lines.** So had `jepa.py:810` (→ 858) and
`defaults.yaml:140` (→ 198) in the same file, `mechanisms.py:544` (→ 540),
`jawp.py:574` in the matrix's WIP row (→ 659), and the six in
`docs/decisions.md` D-013. All are corrected. `docs/related_work.md`, by
contrast, checked out almost entirely clean — it was written against recent
code.

The residual stale citations that remain are **deliberate**: they are the old
line numbers quoted inside text that is being preserved as history, each next
to a note saying they had drifted. Do not "fix" those; they are the record.

If you edit `src/models/*.py`, re-derive the citations in the files listed in
"Current" above. The extraction is ten lines of `re` — see the method section.

- the **open** items in the three wave-1 banners (I4, I9, I11, I12, I13, and
  V8's bundle-path half) — marked OPEN against the code, not fixed;
- the **single live `xfail`** (`TestWSRSamNoSilentSubstitute::test_retraction_preserves_column_orientation`) —
  an open science decision (D-010), not a documentation defect;
- the **WSD↔JAWP conflict** — now recorded in three places and explicitly *not*
  resolved. It is a science decision: whether WSD should track a
  residual-covariance subspace or a variance subspace changes what the paper
  claims.

## Re-running this sweep

The method that found all of the above, in order:

1. `git log --oneline` over the wave commits, to learn *what changed*;
2. grep the prose for every **number** and every **module/metric name**;
3. check each against the code — `param_counts.json` and
   `scripts/results_apparatus.py verify` for config-derived numbers, a direct
   instantiation for model structure, `Select-String` on `src/` for names;
4. extract every `file.py:NNN` citation and print the line it points at — see
   the section above; this is where the cheapest fixes were;
5. for anything you cannot verify, **say so and leave it** rather than
   substituting a plausible number.

A documentation number replaced by a guess is worse than a stale one, because a
stale one gets found and a guess never does.
